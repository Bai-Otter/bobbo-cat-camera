> 本文记录首版原声小剧场。2026-10-29已升级为同一个小剧场的“原声＋稀疏内心独白字幕”，手机页默认目标35秒；新行为、兼容方式和验收见[当前版本](story-inner-monologue-2026-10-29.md)。下文首版时长规则与无字幕说明仅对应历史 `interaction` 模式。

> 同日后续已完成[人宠合拍与丑萌照片](daily-photos-2026-10-29.md)，下文“照片未接入”属于首版历史记录。

本阶段实现两类**视频**，不是四类全部完成。人宠合拍、丑萌照片在页面明确标为“暂未接入”，没有样例图片冒充生成结果。

## 如何使用

在本服务目录准备好现有依赖和模型连接后运行：

```powershell
.venv/Scripts/python.exe run_daily.py --port 8880
```

打开 `http://127.0.0.1:8880/daily`。上传视频，按需调整吃播时长和故事目标，再点击“一起生成两段视频”。同一任务内同时判断并分别剪辑；原调试台仍在这个服务的 `/`，也能从手机页打开对应任务的完整 Prompt、原始拼图、吃播圈选和原始 AI 返回。

`run_daily.py` 默认使用独立的 `data/daily/`，可用 `--data-dir` 指定其他目录。它**不会自动读写另一个正在运行的服务的数据或提示词库**。本机预览初次部署已复制当前已发布提示词库的快照 P0004/revision3，原 8876 服务和畸变实验不改动；之后两个实例的通用标准各自独立。如果需要同步，请显式迁移提示词，不覆盖运行中的数据目录。

首次新安装仍从仓库默认通用全文建立自己的 P0001。版本号是各安装的历史编号，不表示默认审美变回早期版。不要复制密钥或整份私人任务数据来迁移标准。

## 原吃播逻辑保留什么

- 原系统契约全文和当前用户审美提示词不改写；只有启用双视频时追加独立故事契约。
- 吃播依然优先近距离进食、清楚的鼻口脸颊和满屏大脸，站起/远景仅少量点缀。
- 吃播选帧、原有表情包和故事证据分开。不能为补故事，把只有人宠同镜但不适合吃播的帧塞进吃播的 `selected_frames`。
- 默认目标40秒、范围30–50秒。保留原速、原画幅、原声，不新增字幕、配音或 BGM。
- 原调试首页默认仍是吃播模式。未开启 `story_enabled` 的请求和历史输出保持兼容，不补造“当时提取过的小剧场”。

## 什么才算一个互动小故事

人和宠物必须在选中的画面里同时可见，并有可观察的动作与随后回应。按用户参考图，清楚可见的人手、腿或身体可以算“人”，不强求人脸；画外声音、影子或“应该有人”不算。

例如：手靠近 → 猫靠近鼻嘴 → 猫转头看手；人摸猫 → 猫抬头或转身回应。纯共处、人在远处路过、单独猫吃饭或随机漂亮近景不算。是否有真正交互仍由本次模型依据画面判断，不由程序凭标题猜测。

一次只选一个连贯事件，可包含多个原时间顺序的小片段；至少保留动作和反应，不能倒序、重播或把无关事件当一段故事。目标默认约30秒，可设3–60秒；**目标不是最低时长**，事实只有几秒就保留几秒，不用独猫镜头凑长，硬上限60秒。

每段须明确列出其 `[start,end)` 内全部采样帧作为人宠同镜覆盖，并列出事件证据。程序校验所有 ID、真实采样时间、事件先后、动作与反应引用、片内覆盖、无重复区间和时长；不合格就显示未通过，绝不改出一条虚构故事。

## 一次看图，两个产物

1. 沿用默认约每秒一帧、每张最多60格的输入拼图。
2. 所有拼图放进**同一次**既有模型请求，模型额外返回 `interaction_story`。不会先问吃播、再调用一次问故事，也没有自动视觉重试。
3. 本地分别校验两条决定。故事证据不要求先被选成吃播可爱帧。
4. 吃播继续走原来的去重、批准上下文与目标时长处理。故事只在批准人宠同镜区间**内部**对齐真实源帧，不能向外扩大；事件另外保存原片和成片的时间映射。
5. 两条视频分别渲染、完整解码、检查帧数/PTS、画幅和原声轨。增加 `render_story` 独立计时，AI 耗时仍只有一次。
6. 封面用各自最终片内真实的已有采样图，不找网络猫图代替。

沿用已有提供方连接和模型配置，不更换凭证，也不启用客户端兼容伪装。实际请求的模型、图片数、调用次数和完整 Prompt 可在任务中核对。流式响应不完整时仍全局失败，不把半截 JSON 当成两个结果。

## 未生成不等于同一种情况

| 状态 | 意义 |
| --- | --- |
| `ready` | 该类视频通过决定校验和媒体导出，返回真实地址和时长 |
| `not_found` | 识别完成但没有足够素材；故事须明确给出事实原因 |
| `invalid` | 该类模型结构/证据不合格或缺字段，不等于模型确认不存在 |
| `failed` | 该类本地剪辑或校验失败，保留原始决定与错误 |

一类无结果或失败，不抹掉另一类合格成片。如果两类都明确 `not_found`，任务表示“分析完成、无符合条件的视频”，不展示播放器。如果没有任何可交付视频且至少一类出错，任务失败，错误与调试记录保留。取消和源文件完整性异常仍中止任务。

符合既有条件的失败任务可以使用离线恢复工具，仅复用真实完成的 AI 返回和输入缓存，AI 调用为0；新增故事同样经过完整证据与内缩帧边界预检。原任务不改写，不存在“恢复时顺便再问一次AI”。工具仍要求对应服务停止，不支持带人工反馈的迭代任务。

## 从认可的自然独白样片提炼什么

用户认可的旧样片是全长画面、自然短反应、Qwen柔和声、留白和无BGM，不是已经做好的故事短剪算法。这次仅迁移：

- 先写清楚可见事实，再组织“发生什么—怎么回应—接着怎样”。
- 标题和说明自然简短，可爱来自时机与动作，而不是硬卖萌或编动机。
- 靠近手不升级成舔/亲手，走到人旁不直接当求抱，离开不直接当吃饱或生气。
- 保留自然反应，不强制每几秒切一次。

**本阶段不接语音合成、字幕或音乐**，没有把旧样片的14句台词、三分钟长度或声音直接硬套新视频。若后续加入内心独白，应将事实与拟人创作分层，并用实际配音长度重新对齐。

## 数据与提示词存档

任务目录保留原有输入、Prompt和AI原文，并增加：

- `story-decision.json`：故事结构/证据校验结果。
- `story-timeline.json`：实际源PTS剪点、原始批准区间、事件原片/成片时间、所有内缩与证据保留记录。
- `interaction-story.mp4`、`story-technical-validation.json`：合格故事视频与技术检查。
- `story-result.json`：该类别的最终状态、视频和错误。
- `result.json`：原吃播字段加 `highlight_status`、`story`、`poster_url`、`dual_video`。
- `timings.json`：真实分阶段耗时，包含吃播/故事独立渲染和校验细项；子项包含在父项内，不重复计总时长。

新增通用故事契约存档在 `prompts/daily-story-system-appendix.txt`，源码常量为 `vision.STORY_SYSTEM_APPENDIX`。原 P0004 历史及其 SHA 不改写。每个任务的 `prompt.json` 才是该次实际完整输入，不用最新版源码冒充历史 Prompt。

私人录像、人物画面、采样拼图、运行数据与密钥不提交 Git。网页仅供本机调试，不是已做鉴权/隐私授权的公网多用户产品。

## 验证边界

自动化测试既有纯离线模型返回，也有实际FFmpeg生成的测试视频，验证单次输入、双产物、错误隔离、原声/画幅/PTS和恢复；这些合成测试不是“模型看懂了真实猫”的证据。实际提供方试跑另行记录。

首轮真实试跑与手机浏览器验收见 [2026-10-28验收记录](daily-dual-validation-2026-10-28.md)：同一次AI请求得到40秒吃播和11秒互动故事。

约一秒的采样可能漏掉瞬时舔嘴、摸头或短暂遮挡。`co_visible_frame_ids` 是模型对**已给采样**的声明，程序能验字段与时间，不能独立证明画面语义，也不能承诺采样间隙逐帧都同镜。一个episode ID一致不等于已自动证明人物/宠物身份一致。跨家庭、多猫、低光和长视频效果还需要更多真实样本评估。
