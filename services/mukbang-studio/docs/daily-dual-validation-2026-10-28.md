# 双视频首版验收 · 2026-10-28

## 实际交付范围

一次上传、同一组采样拼图、同一次视觉请求，分别得到原声吃播精选和人宠互动小故事。原吃播系统提示词和已发布审美标准保留；双视频模式只追加独立故事契约。照片两类尚未接入，页面明确说明，不展示假结果。本版不加字幕、配音或 BGM。

使用方法与边界见 [双视频说明](daily-dual-videos.md)。独立本机预览：`http://127.0.0.1:8880/daily`；原 8876 服务及其他实验没有被覆盖。8880 的提示词库是初次部署时复制的 P0004/revision3 快照，后续不会自动与 8876 同步。

## 真实模型试跑

使用用户此前提供的184.850秒视频，模型 `gpt-6.1-sol`，当前 P0004/revision3。约每秒一帧，共185张采样、4张拼图。每张最多60格，因此超过180秒会产生第四张，不强行压缩丢帧。

- 实际视觉 POST **1次**，无自动重试、无第二轮模型看图。
- 吃播成片 **40秒 / 800帧**：原片81–104、109–119、138–145秒。
- 互动故事 **11秒 / 220帧**：原片127–138秒，“人扶猫到碗前，猫低头吃”。
- 事件顺序：127–131秒扶到碗前 → 131–133秒猫站稳转头抬脸 → 133–135秒人再次接触肩背 → 135–138秒猫转正、低头进食。
- 故事目标30秒是期望，不是最低长度；没有用独猫画面、重复或无关素材凑时长。
- 两段均通过完整解码、帧数、实际PTS、原速、原画幅、色彩范围及原声轨检查。源视频2560×1440、HEVC/full range，音轨8000Hz单声道；输出保留画幅、有效色彩范围及音轨采样率/声道。

开发者另检查了一张**既有输入拼图**以核对动作，不重新抽帧或发出提供方请求。媒体技术报告中的 `manual_visual_review_count: 0` 是自动媒体步骤的字段，不用它冒充整个开发过程从未人工看图。

## 不夸大的边界

约一秒一次的采样会漏短动作或短暂遮挡。程序能检查模型提交的人宠同镜ID、时间范围和动作/反应引用，不能独立证明画面含义，不能保证采样间隙逐帧同镜。当前只是一个真实样本成功，不是跨家庭、多猫、低光的准确率评测。

本地任务保留实际Prompt、原始模型返回、输入拼图、双成片、各自时间轴、技术校验和耗时。私人录像、人像、截图、运行数据和凭证不提交Git；公开仓库仅存代码、提示词契约、方法和本验收说明。本机预览未实现公网多用户鉴权，不应直接公开。

验收后原计划的独立服务重启命令被本机执行策略拒绝，未停止或重启任何服务。8880继续运行已通过真实试跑的版本；最后补充的启动入口隔离修正已通过3项离线测试，下次正常启动时加载，不影响当前独立数据目录及两段成片的使用。
