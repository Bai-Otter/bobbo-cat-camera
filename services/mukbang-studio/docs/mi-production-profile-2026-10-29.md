## 现在的实际流水线

上传 → 采样拼图 → **一次视觉请求**（吃播/故事/两类照片/咪独白/逐句演绎/额头位置一起返回）→ 选片校验 → 文字TTS → 实际音频时间对齐 → 原片剪辑和额头字幕 → 配音与原声混合 → 本地BGM闪避混合 → 输出验证。

- 吃播P0004不变，照片规则不变。咪风格mi-inner-v1作为小剧场专用系统附加规则启用，不是篡改吃播Prompt。
- 在符合人宠同镜的片段里优先鼻口和猫脸可见的近脸互动、盯食物/够一口/尝到后的反应，降低重复远景站立、后脑勺和人长时间操作的优先级。reason需解释具体好看在哪里。仍有上下文，不只切峰值。
- 所有台词都是猫的念头，使用“咪／本咪”但不每句强加；用认真又天真的小算盘、小得意、给自己找台阶补充画面，不复述“我现在往前挪”。维持稀疏4–6句参考与原时间证据校验。
- 可选performance_direction（最多160字纯文本）随同一次视觉响应返回，传入每句TTS instructions；不进入字幕，不当台词朗读。请求缓存包含实际指令，修改演绎不会误用旧音频。
- 使用用户已确认且声明获授权的已保存克隆ID，不创建新克隆、不上传参考音频。保留音色原生速度/音高，轻快清楚由表演指令控制，避免把已认可声音机械变调。
- 额头字幕forehead-v2保持：无进出特效、按采样位置插值。没有第二轮定位请求。

## 服务专属、可持久配置

私有配置位置：所选data-dir/story-profile.json；可用MUKBANG_STORY_PROFILE_FILE显式覆盖。run_daily.py会设置MUKBANG_APP_DATA_DIR，因而同一数据目录重启后仍读取同一预设，不依赖本次对话的临时环境。缺少配置的其他服务保留旧音频行为；不能仅因为全局代码升级就偷偷替其他服务换声音。

示例结构（仅演示，不包含任何可用凭证或私有音色ID）：

```json
{
  "version": "mi-production-v1",
  "voice_file": "E:/private/authorized-voice.json",
  "music_file": "E:/private/licensed-or-preview-music.wav",
  "music_sha256": "填入已确认音乐文件的64位SHA256",
  "music_label": "已确认音乐",
  "music_rights": "local_preview_only"
}
```

voice_file引用既有包含voice_id的本地JSON，优先于旧MUKBANG_BREEZE_VOICE_ID。仍需要MUKBANG_BREEZE_ENABLED=1和既有BREEZE_API_KEY_FILE。配置无效时不静默回退旧音色；生成明确记录失败并保留可用字幕版。data目录及音频/音色/凭证均不上传Git。

当前8883使用已确认参考分离伴奏，原曲与商用授权尚未确认，仅作为本地预览素材。music_rights只有在实际获得音乐授权后才能设为licensed；付费TTS权益不等于音乐授权。代码不下载、不搜索、不自动更换音乐。

## BGM及故障处理

先校验本地文件SHA256及音轨，再按成片长度循环或截取。基准RMS约-28dBFS并限制峰值，说话前0.18秒渐低至35%，说完0.45秒恢复；音乐头尾0.7/1.4秒淡入淡出仅针对音轨，字幕没有特效。配音混合沿用原声闪避，BGM混合不重新编码画面，并验证视频流哈希、音轨时长及完整解码。

配音失败不再用只有音乐的版本冒充整套效果。BGM失败保留配音版，输出bgm.status=failed和明显警告，不自动换音乐或重复调用模型。story_bgm单独计时并含准备、电平/闪避混合、校验明细。

## 怎么确认真正生效

- GET /api/config：story_production_profile报告预设版本、风格、音色标签、BGM及配音启用状态；不返回私有音色ID和文件路径。
- 每个任务保存实际Prompt；story.style_version基于该任务Prompt而非当前服务配置。
- story.narration记录实际声线/逐句指令；story.validation.bgm_added只有成功合成后为true，story.bgm包含素材哈希、闪避区间及真实计时。
- 手机页顶部显示“新生成用什么”，每条成片显示“本次实际用了什么”。旧记录不会被自动重标成新风格/新音色。
- 此处修复必须通过正常/api/jobs上传验收；独立试听脚本成功不再算生产功能完成。
