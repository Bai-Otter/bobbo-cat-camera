# ADR-0001: 同视频选帧反馈与可比较的手动迭代

## Status

Accepted，跨视频范围由ADR-0002扩展：原帧级纠错仍按同视频、显式手动调用实施；用户随后明确接受将反馈提炼为人工确认的通用Prompt并用于新视频。原局部帧ID不会跨视频自动推广。

## Context

用户不认可部分AI“可爱”选择；仅看最终成片或编辑泛化Prompt无法定位漏选/误选。需要给具体帧正负例、解释原因、重选并比较，同时控制多模态调用成本，保留原始决定与每轮耗时。历史任务没有精确反馈记录，不能伪造训练样本。

## Decision

沿用本地文件任务与当前gpt-6.1-sol，不增加数据库、训练或自动优化代理。闭环为：

`原任务/任意一轮 → 全部采样帧与已选帧 → 保存反馈草稿（0次AI） → 用户点击带反馈重选（新一轮1次AI） → 新旧结果及未满足反馈对比`。

每轮为独立任务，保留root_job_id/parent_job_id/round；复用原源片、时间戳及输入拼图，抽样间隔固定。重选不重新抽帧；输入hash与源时间映射核验失败就停止，无隐式回退或重试。原图、各轮圈选、Prompt、反馈快照、原返回、成片和timings均保留。

反馈是完整快照：annotations为frame_id、like/dislike及可选reason，另有当前视频整体note。未标注为中性。like优先保留，受时长等约束时报告漏选；dislike禁止作为selected_frames里的可爱证据，若AI仍选则可见失败并保留原返回，不偷偷声称已纠正。dislike不等同逐帧删除前后整段画面，网页明确说明。整体片段裁剪仍沿用可审计的AI时间轴。

反馈草稿带版本号；PUT完整替换并校验expected_version，清除不会被祖先意见重新合并。生成请求带request_id和冻结选项，服务端幂等；重复点击或响应丢失后的手动重试不创建第二个相同任务。不自动发送AI请求。分支轮次在同一家族内唯一递增，不覆盖旧版本。

自动对比只显示新增、移除、保留的帧，以及喜欢被选/漏选、不想要仍被选/已排除；不把这些数值称为审美准确率，不保证每轮一定更好。反馈及原因作为数据进入真实Prompt，不能修改系统安全或JSON规则。文本仅作为文本渲染；当前密钥误贴需脱敏，任务路径必须保持在指定job目录内。

## Consequences

正向：用户能定位漏选与误选，知道每轮有没有改对；同一采样坐标使对比可解释；节约重复前处理；成本按用户主动轮次可数；失败可回看且历史不丢。

代价：每次重选仍有一次多模态调用和剪辑成本；一秒抽样仍可能错过动作；“喜欢”不等于必塞进片；负例违反会失败，需要用户决定是否继续；当前不学习跨视频规则，也不微调模型。

## Alternatives Considered

- 只让用户修改Prompt：简单，但无法准确表达哪帧选错或漏选，可作为补充note保留。
- 全手工剪辑或立即训练偏好模型：前者不解决AI审美校准，后者缺足够干净标签且显著增加成本/运维，暂不实现。
- 每次重传重抽帧：比较基准可能变化且浪费前处理，改为复用已验证输入。
