# ADR-0002: 以可确认、可回退的Prompt承载跨视频审美调优

## Status

Accepted：用户明确要求把视频纠错迁移到其他视频，并接受AI提议规则、人工确认后发布，指定提示词为主要调优载体。本决策扩展ADR-0001的“仅同视频”范围，但不改变原有局部反馈、缓存复用和单次视觉请求的边界。

## Context

帧级反馈可以纠正同一条视频，却无法直接迁移帧编号到另一条视频。需要把具体意见提炼为通用审美标准，并确认文字规则实际改变了哪些内容，避免单条样例导致过度概括。没有足够数据或必要性引入模型权重微调、向量数据库或图片检索。

## Decision

增加一套本机通用Prompt版本库。每版全文不可变，包含父版、创建时间、确认的修改摘要、程序计算的文本差异、可选建议来源。全局指针指向当前生效版本；发布新版本或切回历史版本均由用户显式操作、持久保存，严格revision检查防止陈旧页面覆盖。切回旧版也递增revision，防止ABA。

保留两个独立动作：同视频“带反馈重选”仍是一次视觉请求；“整理成通用Prompt”是额外一次纯文字请求、零图片。后者只取用户已保存且版本匹配的反馈、原因和整体意见，以及明确标为AI旧解释的辅助文字，不能把旧模型理由当成用户偏好，也不能假装重新理解了画面。跨多个来源以job_id命名空间区分相同帧ID。信息不足须提示，不能凭一个like臆造视觉特征。

建议保存候选全文、修改解释、证据、警告、原返回和真正diff，但不自动发布。用户可先编辑候选并确认生效。旧版基线发生变化后，不允许悄悄把旧建议套到新基线；候选/手稿保留供重新比较。通用全文不携带局部帧ID，源帧/来源记录只保留在建议溯源中，不拼到未来视频请求里。

后续新视频默认使用服务端当前生效版，在接受请求时冻结实际全文、版本、revision和摘要。单次自定义Prompt仍受支持，但不会自动发布；打开旧任务仍显示其实际Prompt，历史任务不会因为全局标准变化而被改写。当前任务如果需要采用新生效标准，必须由用户明确选择。

建议、发布和激活均带幂等request_id，未知响应只允许用户手动确认同一冻结请求，不自动重试。建议任务复用后台单工作者，独立展示纯文字调用次数、零图、用量和耗时；失败和重启不产生第二次请求。密钥误贴需脱敏，模型/用户文本仅作为文本渲染。

## Consequences

后续扩展：在保留以上纯文字入口的同时，增加“将这个满意版本设为通用”。它冻结选定成功轮次的实际模板、原始拼图和已应用反馈，额外最多一次多图请求，生成独立候选；仍需人工确认发布，且同时保护该轮模板与当前通用基线的技术限制。正常视频生成的单次视觉预算不变。详细字段与边界见接口说明的满意轮次提炼部分。

反馈可持续整理进可编辑的跨视频标准；每条规则修改可追溯、可回退，新片采用版本可核对。单次视频视觉预算不变，但用户主动整理通用建议会增加一次文字模型调用。规则是否泛化须用未参与调试的视频对照检验；机制可迁移不等于每轮质量必然更高。

## Alternatives

- 只持久保存手动Prompt：最省模型调用，保留为手动编辑发布入口，但不自动整理具体反馈。
- Prompt加正反例图片：视觉审美更具体，增加图片输入与成本；此阶段按用户要求先以文字为主，不自动加入。
- 权重微调：需要较大、干净且多样的训练评估数据和额外运维，本阶段不采用。
