# BOBBO 吃播调试台

[返回项目首页](../../README.md)

上传猫咪视频 → 抽帧拼图 → 一次多图 AI 选片 → 自动导出精选和独立表情包。可以核对原始拼图、AI 圈选、完整 Prompt、实际时间轴与分阶段耗时，再用反馈逐轮调整。

这是独立的本机调试服务，不替换仓库原有 `server/` 或 `vision/`，不需要微信小程序、摄像头 SDK、本地检测权重或音乐文件。没有自动接入每日吃播生产链路。

新增 [每日双视频手机预览](docs/daily-dual-videos.md)：保留原吃播规则，在同一次多图请求中额外提取人宠互动故事，分别输出两段原声视频。运行 `python run_daily.py --port 8880` 后打开 [手机预览](http://127.0.0.1:8880/daily)；该入口默认用独立 `data/daily/`，原调试台仍保留。

当前手机页默认使用 [内心独白升级版](docs/story-inner-monologue-2026-10-29.md)：小剧场目标35秒（通常30–40秒），保留原声，烧录稀疏的可爱内心独白字幕，可查看逐句原片/成片时间和下载SRT。可显式启用 [Breeze固定音色配音](docs/breeze-narration.md)，按实际声音长度调整字幕并分别统计语音生成和混音耗时；仍只有一个小剧场，不加BGM。未配置时维持原声字幕版，旧记录保持旧版标签。若已有旧进程，请先确认无运行任务再重启加载新代码。

新增 [单次API额头综艺字幕](docs/head-top-captions-2026-10-29.md)：在原先那一次多图识别中同时返回猫头框与可选额头点，程序让浅黄色描边字幕贴近额头、按采样位置平滑跟随，直接出现/消失，无淡入淡出、缩放或弹动。旧响应只有头框时用上段几何估计；定位不足回退安全位置。没有第二轮定位请求，也不依赖本地猫头检测模型。新上传的内心独白模式自动使用；历史成片不会被覆盖。`/api/config` 的 `story_caption_layout: "forehead-v2"` 可确认服务已加载新版。当前授权克隆+BGM仍是独立试听样片，不因本功能上线而切换默认音色/音乐。

后续已补齐 [两类照片](docs/daily-photos-2026-10-29.md)：手机页默认一次生成两段视频及人宠合拍/丑萌照片，各类独立状态；照片原尺寸、可打开/下载、可核对采样帧和选择理由。图片提取单独计时，不增加模型调用。照片版独立验收入口为 `python run_daily.py --port 8882 --data-dir data/daily-photos`；原8881样片仍保留。新实例的数据和提示词库独立，不会自动同步其他实例的修改。

**当前照片规则已更新为 [合拍＋丑萌相册](docs/photo-gallery-2026-10-29.md)**：有人宠同镜就选一张最好合拍，手/腿/身体局部也算；丑萌至少4张、通常4–6张，强调不同表情和角度。手机页发送 `photo_mode:"gallery"`，旧单张接口/记录仍兼容。新版独立预览：`python run_daily.py --port 8883 --data-dir data/daily-photo-gallery`，打开 `/daily`。8882是上轮单张实例，未重启加载新代码前只用于回看。

最新审美为 [closeup-v2](docs/closeup-photo-refinement-2026-10-29.md)：丑萌主打贴镜头、夸张透视的大鼻头与鼻口，明显吐舌仅少量补充，不再用普通圆脸/偏头凑数；合拍优先亲亲、贴脸和抱抱。仍以至少4张为目标，素材不足则注明。照片规则独立升级，原吃播P0004和小剧场提示词不变；8883保留历史，新上传沿用新规则。

## 启动

需要 Python **3.11+**、可在 PATH 找到的 **FFmpeg / ffprobe**，FFmpeg 应包含 `libx264` 和烧录字幕所需的 `libass`；系统应安装中文字体（Windows优先使用微软雅黑）。Node.js **18+** 仅用于前端测试，运行网页不需要 Node 或打包步骤。

在仓库根目录进入本服务：

```powershell
cd services/mukbang-studio
```

Windows 一键准备依赖并启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./start.ps1
```

打开 [本机调试台](http://127.0.0.1:8876/)。首次启动会联网安装 Python 依赖，不会自动调用 AI。已有其他实例占用该端口时，不要同时启动；也可按下面方式选择其他端口。

手动安装与启动（Windows）：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe run.py --port 8876
```

macOS / Linux 使用相同服务代码：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py --port 8876
```

服务仅监听 `127.0.0.1`。源码采用跨平台路径；本次同步实际在 Windows / Python 3.12 上验证，未声称完成其他系统的实机验收。

`requirements.txt` 声明兼容范围；如需复现本次测试的依赖版本，可改为安装 `requirements-lock.txt`（同步时的 Python 3.12 / Windows 版本快照）。

## 配置模型

新安装不带任何密钥，也不自动读取其他软件的账号。可先启动页面，在“模型连接”填写自己的地址、模型名、接口格式与 API Key；手动输入的密钥只保留在当前服务进程内存中。

需要重启后保留配置时，在本服务目录复制并编辑示例：

```powershell
Copy-Item .env.example .env
```

替换示例域名，填写自己的凭证。示例模型名为本轮已使用的 **`gpt-6.1-sol`**；它是服务商提供的模型标识，不是仓库自带的模型。服务必须支持多图输入，以及所选 `responses` 或 `chat_completions` 格式。具体名称、接口格式与可用性以你自己的提供方为准。未配置 `.env` 时的后端兼容默认值不等于已经连接了可用模型。

`.env` 只解析允许的变量，不执行脚本；已有进程环境变量优先。请不要提交 `.env`、API Key 或真实配置。

AI 单请求默认最多等待 **600 秒**，可在 `.env` 中以 `MUKBANG_VISION_TIMEOUT_SECONDS` 设置 **30–1800 秒**的有限数值，重启服务生效。实际值可在配置接口和任务请求清单里核对。超时保留已收到的返回，不自动再发请求；延长等待不保证远端一定成功。

逐帧时间戳读取默认使用 **4 个解码线程**，避免本次 Windows 笔记本上自动线程过多造成的明显开销。`MUKBANG_FFPROBE_THREADS` 接受 **0–32** 的整数，`0` 恢复 FFmpeg 自动设置；只影响 ffprobe 的帧扫描，不改变主片编码线程、画幅、帧率或画质。不同机器可按实测调整。

可选复用你自己的现有 Codex provider：将 `MUKBANG_VISION_USE_CODEX_PROVIDER` 设为 `1`，必要时通过 `MUKBANG_CODEX_HOME` 指向本机配置目录。服务只读当前 provider 和凭证，不复制或修改原文件；重启会重新读取。不要把 `config.toml` 或 `auth.json` 放进仓库。网页中更换服务域名但未提供新密钥时，会清空旧密钥，防止误发。

如自己的中转明确要求 Codex 客户端标签，可显式设置 `MUKBANG_VISION_CODEX_CLIENT_COMPAT=1` 后重启。默认关闭，网页不能启用；只对本次启动导入且未更改的完整地址、模型和 Responses 格式生效。实际手动更改地址、模型、接口或凭证后即停用，不会因改回原值自动恢复。它仅增加 `User-Agent: codex_cli_rs/0.156.1` 和 `originator: codex_cli_rs` 两个公开标签，不复制会话、账号归属或认证签名。模型、Prompt、图片、原有凭证、总时限和一次请求规则都不变；配置接口的 `client_compatibility` 与任务请求清单的 `client_headers` 可核对生效情况，不记录 Authorization。标签只是本机 CLI 版本的兼容候选，不保证获得服务商授权或通过更严格校验；仍被拒绝时不会尝试其他伪装或自动重试。关闭请设为 `0` 并重启。

本机 2026-10-23 的一次真实验证仍被中转以官方客户端限制拒绝（403），实验后已关闭开关；不代表连接已修好。结果、调用次数与验证边界见 [兼容实验记录](docs/client-compatibility-2026-10-23.md)。

远程手动连接要求 HTTPS，本地模型可用 localhost HTTP。显式继承的既有远程 HTTP provider 有完整地址限定的兼容例外，网页会持续提示明文传输风险；建议切换 HTTPS，不建议在公网明文发送图像和凭证。

## 生成与反馈

1. 上传视频，设置目标时长及最短 / 最长。默认 **40 秒**，范围 **30–50 秒**；实际参数一起写入发给模型的 Prompt。
2. 点击生成。结果提供精选 MP4、独立 GIF / MP4、AI 输入原图和圈选图、选帧理由、源片与成片时间轴、原始返回、技术检查和耗时。
3. 选得不合心意时，在已选或全部抽样画面中标记“喜欢 / 不想要”，尽量填写具体原因，再保存反馈。保存本身不调用 AI。
4. 点击“应用反馈，生成下一版”，复用源片、采样和原始拼图，再进行一次带反馈的视觉选择与剪辑。各轮结果和实际 Prompt 独立保留，可对比新增、移除与未满足的反馈。

“喜欢”优先考虑，但不保证无视时长全部放入；“不想要”禁止被模型作为可爱证据选中，不等于逐帧删除其附近整段原片。违反负例会明确失败，保留原返回，不偷偷替模型改答案或自动重试。

## 将满意结果设为通用标准

仓库的 [默认提示词](mukbang/default_prompt.txt) 是同步时本机已确认发布的 **P0004「满意第 2 轮 · 通用标准」**全文，不是尚未确认的候选。核心偏好：近距离进食占主体、可辨认的鼻口和满屏大脸优先，不把大额头当贴脸；轻微偏脸或半眯眼也可保留，站起和远景只少量点缀。

新安装首次启动会以这段全文建立自己的 **P0001**，从新的版本历史开始。没有复制本机版本库、视频、反馈或候选记录。已有安装会保留其本地标准，修改源码默认文件不会覆盖已有库。原始版本号与全文摘要见 [导入清单](docs/source-manifest.json)。

在页面中，满意后使用“将这个满意版本设为通用”：

1. 核对正在显示的成功轮次，点击“结合这一轮画面整理候选”。发送该轮原始拼图、真实模板、选中样本与已应用的冻结反馈，额外最多一次多图 AI 请求；不混入后来未应用的反馈草稿，不重新抽帧或剪片。
2. 核对候选全文、修改差异、来源和调用记录。在**候选底部**勾选确认框，再点击“确认设为通用”。上方手动编辑稿有自己独立的确认框。
3. 发布不调用 AI。后续新视频默认采用当前生效版；历史任务不改写，也可以明确回退标准。若候选生成期间通用基线变更，需重新核对，不能静默覆盖。

也保留“整理成通用 Prompt”的多来源纯文字入口：只整理明确保存的文字反馈，最多一次文字请求、零图片。可直接手动编辑和确认发布。所有方法都以 Prompt 承载偏好，**不是模型权重微调**；可跨视频使用不等于已验证所有新视频的审美效果。

## AI 调用与画面边界

- 默认每 1 秒抽一帧，每张拼图最多 60 帧；恰好三分钟、正常帧率素材通常得到 180 个样本和 3 张图，一次请求发送所有图。抽样不是看完源片全部原始帧，短暂舔嘴、露牙可能漏掉。
- 每次视频生成或反馈重选最多一次模型 POST；无自动 AI 重试。主动重选是新的调用，可能再次计费。满意轮次看图提炼、纯文字整理分别单独计数，不伪装成免费步骤。
- 视觉请求默认总时限 600 秒（可配置 30–1800 秒）；流式内容未完成也会中止并保留已有返回，不把半截 JSON 当成功。引用帧必须处于模型批准的真实时间范围内，越界则本轮失败，不自动扩大范围或重新请求；仅可按下文规则收敛多余引用。
- 模型返回选中帧、精选时间轴和表情包时间轴。算法可去重、对齐帧边界，并仅在模型认可的连续上下文内补长；不能重复、变速或拿无关画面凑时长，素材不足会显示警告。
- 导出保留原速、显示画幅和原声，**不添加 BGM、配音、字幕或贴纸**。表情包不自动循环插入主片。输出做 H.264、像素格式 / 色阶、尺寸、音轨、时间轴和完整解码检查。
- 原拼图不改写，圈图另存；红圈表示 AI 直接选中样本，黄色 MEME 表示表情包引用。
- 单视频上限 512 MB / 10 分钟；最多 3 个等待或运行任务，一个后台工作者。取消为协作式，已发送的模型请求可能仍要等返回或超时，也可能计费。

## 耗时和本机数据

页面显示每轮总耗时，以及接收保存、排队、源信息、抽帧、拼图、准备 Prompt、AI 请求、选择验证、圈图、精选剪辑、表情包和最终检查等环节。反馈重选标为复用采样缓存。统计从本地服务收到请求到处理结束，不包含请求抵达前的上传时间、用户操作或页面轮询延迟；AI 请求包含编码、传输、等待和接收。

新任务还会缩进显示源片索引、编码、输出元信息、逐帧时间轴检查、完整解码和 GIF 检查等细项；这些已包含在所属环节内，不再相加。旧任务不补造内部明细。MP4 的计帧与时间戳检查共用一次扫描，表情包 MP4/GIF 共用一次源片解码；GIF 直接来自未编码画面，不经过有损 MP4 二次取材。主片编码参数和质量检查不因提速而取消。

数据保留在本服务的 `data/`，默认不自动清理，且已被 Git 忽略：

| 位置 | 内容 |
| --- | --- |
| `data/jobs/<任务ID>/` | 上传源片、采样、原图与圈图、实际 Prompt、模型原文、时间轴、精选和表情包 |
| 同目录 `timings.json` | 分阶段耗时、统计范围、失败 / 中断状态 |
| 同目录 `feedback-draft.json` / `feedback.json` | 已保存草稿 / 本轮实际应用的冻结反馈 |
| `data/prompt-library.json` | 已发布通用全文、版本和生效指针 |
| `data/prompt-proposals/` | 看图或纯文字候选、请求记录、来源、差异和用量 |

AI 提供方会收到拼图和文本，不是整段源视频；拼图仍可能包含家庭隐私。请确认服务商的数据与存储政策。备份和分享 `data/` 时也应按私人资料处理，不要提交 Git。

## 离线恢复与历史导入

AI 已完整返回但选片验证或媒体导出失败时，可核验已保存决策，仅补本地处理。只有仍能通过证据验证的决定才可恢复。先确认没有运行任务或候选整理任务，再停止**对应数据目录**的服务：

```powershell
.venv/Scripts/python.exe scripts/recover_render.py <原失败任务ID> --port 8876
```

脚本核验 Prompt、请求与真实响应、输入缓存及决策，创建新的恢复任务，原记录不覆盖，AI 调用数为 0。证据不全、源任务不受支持或对应端口仍在运行会拒绝；没有重新请求 AI 的回退。重新启动后可在任务列表查看。

对于 AI 多引用了区间外采样帧的情况，本地程序只可删除已知且已被 AI 选中的多余引用：精选按原批准上下文、表情包按原片段区间判断，不移动剪点、不扩大上下文、不补造证据。每段仍须包含至少一张原引用帧，否则拒绝。原始 AI 选帧与返回保留；移除记录及真实时间在结果的提示和调整明细中可见。未知帧、未选帧、人工“不想要”帧或不完整响应不能通过此处理绕过验证；带人工反馈的任务暂不支持离线恢复。

历史导入是独立维护工具，需自己准备符合旧格式的资料，仓库不附私人历史素材：

```powershell
.venv/Scripts/python.exe scripts/import_legacy.py --source-project <旧格式资料目录> --run-id local-history
```

它将已保存峰值映射到最近采样格，不产生新的 AI 可爱判断。新安装没有历史结果；不要把历史映射圈图当成新模型认可。

## 安全和商业化边界

这是无多用户认证的单机调试原型，**不要直接开放公网或改为 `0.0.0.0` 提供公共服务**。现有措施包括同源写入、Host 限制、安全响应头、任务路径检查、无 shell 的媒体调用、媒体协议 / 容器白名单和凭证脱敏。

尚未提供域名出站网络隔离、严格流式上传 / 响应限额、独立进程沙箱、用户权限与资源配额、数据回收。部署为多用户产品前应补齐这些措施，并用未参与调试的多样视频验证选片质量、遗漏率、耗时与成本。自动化测试不代表真实模型准确率或产品实机验收。
