现有调试台优先使用 `data/prompt-library.json` 里已发布的生效标准。该数据文件含本机历史，整体被 Git 忽略；仅同步 Python 源码或默认文件，并不能证明当前已发布内容被备份。因此本次通过只读接口提取已发布全文，单独保存到这个目录。

## 后续怎样及时保存

网页“确认设为通用”只发布到本机提示词库，**不会自动提交或推送 GitHub**。这次也没有安装自动同步任务。

每次发布满意的新版本后，按下面流程更新仓库：

1. 只读核对 `/api/prompt-library` 的 `active_version_id`、`revision` 和已发布全文，不能把未确认的候选当成当前版。
2. 在 `versions/` 新增该版本全文，保留旧版本；若换了独立安装，先区分来源，不能用重置后的版本编号覆盖旧档。
3. 更新 `current-user-prompt.txt`，新增当天的快照清单，记录生效版本、SHA256、必要参数和核验范围；保留历次快照。
4. 若系统规则或方法改变，同时更新系统规则快照、方法文档及对应源码。真实目标时长、帧映射和冻结反馈仍由请求构建器动态附加，不写死到通用审美正文。
5. 对比全文和摘要，检查 Git 待提交清单，再明确提交、推送并核对远端提交号。仅在本地保存文件或生成 commit，不代表 GitHub 已保存。

文本使用 UTF-8 / LF；本目录的 `.gitattributes` 固定换行，避免 Windows 检出后因 CRLF 使字节摘要失效。快照中的路径相对本目录，仓库默认文件路径也显式记录。
